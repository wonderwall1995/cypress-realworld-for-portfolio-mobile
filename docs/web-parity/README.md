# 웹과 모바일 기능 일치 작업 안내

모바일 사용자가 웹과 같은 서버 규칙으로 계좌를 만들고, 입금과 이체를 처리하고, 결과를 확인할 수 있도록 하는 작업 지침이다. 모바일 개발 담당자는 **서버 계약 → 기능 → UI와 UX** 순서로 읽고 적용한다.

기준일은 2026-11-23이다. 웹 작업본 `58ed97b4d2cdd53b09027d16bf88a43654d2dce6`, 모바일 작업본 `cbc929404c7905ad53c306fd1463f8fd4cf87a6e`의 현재 소스를 비교했다. 웹의 기존 미커밋 작업과 모바일의 기존 README 수정은 이 작업의 변경 대상이 아니다.

## 읽는 순서

1. [서버 계약과 연동 예외처리](01-server-contract.md): 현재 API, 오류 분류, 서버에 요청할 보완.
2. [기능별 차이와 작업 항목](02-feature-parity.md): 이미 있는 기능, 부족한 처리, 완료 조건.
3. [사용자 흐름과 UI UX 보완](03-uiux.md): 빈 상태, 처리 중, 실패, 복귀 화면의 행동.

## 우선 판단

입금, 계좌별 잔액, 계좌 선택 이체, 비밀번호 재확인, 전체와 내 거래 탭, 실시간 알림은 이미 앱에 있다. 이 기능을 새로 만드는 대신 **세션 만료, 송신 후 결과 불명, 잔액 갱신 실패, 오래된 응답, 서버의 새 거절 규칙**을 보완하는 것이 우선이다.

| 순위 | 작업 | 사용자에게 필요한 이유 |
| --- | --- | --- |
| P0 | 송신 후 결과 불명과 재전송 규칙 정하기 | 응답을 못 받았다고 같은 입금이나 이체를 다시 보내지 않게 한다. |
| P0 | 보호 API의 401과 오프라인 구분 | 로그인 만료와 통신 실패를 구분하고 다음 행동을 제공한다. |
| P0 | 처리 중 창 닫기와 화면 이탈 통제 | 처리한 결과를 잃거나 엉뚱한 화면이 닫히지 않게 한다. |
| P1 | 잔액 새로고침의 부분 실패 표시 | 오래된 잔액을 최신 값으로 오해하지 않게 한다. |
| P1 | 사용자 전환과 필터 변경 중 오래된 응답 차단 | 다른 계정이나 다른 조건의 내용이 섞이지 않게 한다. |
| P1 | 좋아요 409와 계좌 60개 제한 안내 | 서버가 이미 정한 규칙을 앱에서도 이해할 수 있게 한다. |
| P1 | 계좌 없는 사용자의 선택적 등록 흐름 | 계좌를 만들기 전에도 홈, 설정, 로그아웃을 사용할 수 있게 한다. |
| P2 | 글자 확대, 접근성, 안내 문구와 기존 문서 정리 | 작은 화면에서도 완료와 실패를 읽고 조작하게 한다. |

P0는 금액을 다루는 데모를 안정적으로 시연하기 전에 우선 처리할 항목이다. P1은 기능 일치 작업, P2는 마무리 항목이다. 순위는 이번 비교에 따른 제안이다.

## 적용 범위

- 현재 결과는 소스 비교에 따른 문서다. 앱 코드, 서버 코드, DB, 테스트 코드는 변경하지 않는다.
- 실제 서버와 앱을 연결한 재현, Android 실기기, iOS, 모바일 망 전환, 프록시의 장시간 SSE 연결은 이번 문서 작성에서 검증하지 않았다. 코드상 위험은 재현이 필요한 경우를 표시한다.
- 웹에서 쓰는 서버를 공통 기준으로 삼는다. 서버 보완은 모바일 저장소에서 직접 구현하지 않고 웹 담당자에게 전달한다.
- 앱의 하단 탭, 네이티브 뒤로 가기, 키보드 대응은 유지한다. 웹 화면의 배치 자체를 복제할 필요는 없다.
- 테스트 구조와 시나리오는 사용자가 설계한다는 모바일 `LLMS.md` 규칙을 유지한다. 아래 완료 조건은 제품 동작 기준이며 테스트 파일 생성 지시가 아니다.
- 모바일 `LLMS.md`의 결정 대기 항목 33과 41은 자동으로 확정하지 않는다. 외부 입금의 소통 UI, 설정 이름 순서, 계좌 없는 사용자의 화면 정책은 별도로 표시했다.

## 구현 전 확인할 결정

1. 계좌 없는 사용자는 홈 진입을 허용하는 방향을 권장한다. 현재 앱의 온보딩에는 로그아웃 버튼이 있으므로, 로그아웃이 막혔다고 판단하면 안 된다. 홈과 다른 탭에 들어가기 전에 계좌 등록을 강제하는 부분이 웹과 다르다.
2. 예전 기본 공개 범위 `contacts`는 자동으로 `public`으로 바꾸지 않는 방향을 권장한다. 비공개로 전환하거나 다시 선택하게 하는 정책을 정한다.
3. 외부 입금 항목에서 좋아요와 댓글을 숨길지 결정한다. 웹 목록과 상세도 현재 동일한 정책이 아니므로 웹과 앱에 함께 적용할 기준이 필요하다.
4. 서버가 입금과 이체의 중복 요청을 식별하도록 할지 정한다. 기존 조회만으로 결과를 확인하는 방안은 임시 완화이며 중복 처리 방지를 보장하지 않는다.
