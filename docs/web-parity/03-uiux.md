# 모바일 사용자 흐름과 UI UX 보완

사용자는 웹과 앱에서 같은 계좌·금액·공개 범위·처리 결과를 확인할 수 있어야 한다. 모바일에서는 하단 탭을 유지하면서 입력 중 키보드, 뒤로 가기, 앱 중단과 복귀까지 포함해 흐름을 완성한다.

## 계좌를 등록하지 않은 첫 방문

권장 흐름은 로그인 → 홈 → 필요한 순간 계좌 등록이다. 계좌가 없다는 이유로 홈과 설정을 막지 않는다. 입금과 이체를 누르면 필요한 이유와 “은행 계좌 만들기”를 보여 준다. 등록을 취소하면 원래 화면으로 돌아오고 로그아웃은 항상 가능해야 한다.

현재 앱은 온보딩 중 홈을 열 수 없지만 로그아웃 버튼은 있다. 선택적 등록과 메뉴 강조는 `LLMS.md` 항목 41의 결정 사항이므로 이번 문서에서는 제안으로 둔다. 이미 별도 안내 문구를 넣지 않기로 한 기록을 자동으로 뒤집지 않는다.

## 돈을 보내거나 넣는 화면의 상태

| 상태 | 사용자에게 보일 내용 | 허용할 다음 행동 |
| --- | --- | --- |
| 입력 전 | 선택한 계좌, 금액 단위, 필요한 입력 | 입력, 취소, 계좌 변경 |
| 입력 오류 | 잘못된 필드 옆의 구체적인 이유 | 값을 고친 뒤 제출 |
| 전송 중 | “처리 중입니다”와 진행 표시 | 중복 제출 차단. 창 닫기와 뒤로 가기는 전송 상태에 맞춰 일관되게 처리 |
| 서버 거절 | 계좌 잔액 부족, 비밀번호 오류 등 이유 | 이유에 맞는 재입력·재선택. 기존 금액과 메모 유지 |
| 결과 불명 | “응답을 받지 못해 처리 결과를 확인할 수 없습니다” | 내역과 잔액 확인. 자동 재전송 금지 |
| 서버 승인 | 입금 또는 이체 완료와 금액·계좌 요약 | 목록 돌아가기, 다른 거래 시작 |
| 승인 후 조회 실패 | “처리는 완료됐지만 최신 잔액을 불러오지 못했습니다” | 조회만 다시 하기 |

취소 버튼은 전송 전 입력 취소와 전송 후 요청 취소를 혼동시키면 안 된다. 이미 서버에 보낸 작업을 창 닫기로 되돌릴 수 있다는 문구를 쓰지 않는다. 프로세스가 종료된 뒤에도 결과를 찾을 수 있게 하는 계약은 서버의 중복 요청 방지와 함께 설계한다.

현재 입금 창은 전송 중 취소와 바깥 탭 닫기를 허용한다. 이체 창은 바깥 탭을 막지만 시스템 뒤로 가기의 처리 중 정책은 별도 보완 대상이다. 화면 이탈 재현은 Android 뒤로 가기와 제스처를 포함한다.

근거: M `features/bank_transfers/deposit_dialog.dart`, `features/transactions/create/password_confirm_dialog.dart`.

## 이체 확인 화면

사용자는 “정말 이체하겠습니까?” 아래에서 보내는 계좌, 받는 사람, 받는 은행과 끝 4자리, 금액을 확인하고 자기 비밀번호를 입력한다. 현재 계좌 선택의 60 대 40 배치는 유지할 수 있지만 은행 이름이 길어도 금액과 끝 4자리를 읽을 수 있어야 한다.

비밀번호 오류는 입력칸 근처에 두고, 계좌 삭제나 권한 오류는 계좌 선택으로 돌아가는 행동을 준다. 잔액 부족은 비밀번호 재입력으로 해결되는 것처럼 안내하지 않는다. 키보드가 열린 상태에서 요약, 오류, 비밀번호 칸, 확인 버튼까지 스크롤로 접근할 수 있어야 한다.

## 잔액과 새로고침

내 계좌 화면의 합계는 현재 활성 계좌 잔액의 합이다. 거래 줄의 잔액은 “거래 후 잔액”이다. 두 값을 같은 의미로 표시하지 않는다. 조회가 실패했을 때 0으로 대체하면 실제 무잔액으로 오해하므로 마지막 값과 갱신 실패를 함께 표시하거나 값을 확인할 수 없다고 안내한다.

“금액 변동이 생겼어요” 안내는 새로고침 버튼을 누르는 순간 지우지 않는다. 필요한 조회가 끝날 때까지 진행 상태를 보이고, 실패하면 다시 조회할 수 있게 남긴다. 화면에 있는 여러 잔액 중 일부만 갱신되었으면 그 사실을 읽을 수 있어야 한다.

앱 복귀 때는 알림 연결만 복원하지 말고 잔액도 확인한다. 잠든 동안 다른 기기에서 입금했거나 알림을 읽어 버린 상황에서도 현재 잔액을 볼 수 있어야 한다.

근거: M `features/notifications/notification_live_sync.dart`, `core/session.dart`; W `apps/api/src/notification-routes.ts`, `account-money.ts`.

## 빈 상태와 실패 화면

| 화면 | 상태 | 권장 문구와 행동 |
| --- | --- | --- |
| 거래 목록 | 거래 자체 없음 | “아직 거래가 없습니다.” |
| 거래 목록 | 적용 조건에 결과 없음 | “조건에 맞는 거래가 없습니다.”와 필터 초기화 |
| 거래 목록 | 첫 조회 실패 | “거래를 불러오지 못했습니다.”와 다시 시도 |
| 거래 목록 | 다음 페이지 실패 | 기존 목록 유지, 아래쪽에 “다음 거래를 불러오지 못했습니다.”와 재시도 |
| 거래 상세 | 404 | “거래를 찾을 수 없거나 볼 수 없습니다.”와 목록 돌아가기 |
| 계좌 선택 | 내 계좌 없음 | 필요한 이유와 계좌 만들기. 선택적 등록 정책에 맞춰 적용 |
| 상대 계좌 선택 | 상대 계좌 없음 | “받는 사람이 사용할 수 있는 계좌가 없습니다.”와 상대 다시 선택 |
| 사용자 검색 | 검색 결과 없음 | “일치하는 사용자가 없습니다.”와 검색어 수정 |
| 알림 | 미읽음 0개 | “읽지 않은 알림이 없습니다.” |
| 시작과 복귀 | 네트워크 실패 | “서버에 연결할 수 없습니다.”와 연결 다시 확인 |
| 보호 화면 | 로그인 만료 | “로그인이 만료되었습니다. 다시 로그인해 주세요.” |

확인할 수 없는 데이터는 “없음”으로 바꾸지 않는다. 오류 문구 뒤에는 사용자가 실제로 복구할 수 있는 버튼을 둔다. 서버의 내부 오류나 긴 영문 메시지를 그대로 붙이지 않는다.

## 읽을 수 있는 결과와 접근성

설정 저장 결과 자리의 현재 고정 높이 20은 긴 실패 문구나 큰 글자에서 잘릴 수 있다. 최소 높이를 확보하되 여러 줄로 늘어나게 한다. 성과 이름 순서를 바꿀지는 기존 결정 대기 항목을 따른다.

받은 돈의 녹색 +, 보낸 돈의 빨간색 -는 유지하고 “입금”과 “출금”을 함께 읽게 한다. 색만으로 결과를 전달하지 않는다. 은행 이름을 줄이더라도 상세나 접근성 설명에서 전체 내용을 확인할 수 있게 한다. 로딩, 완료, 실패 상태는 스크린리더에도 전달한다.

작은 화면, 긴 이름·은행명·메모, 글자 확대, 키보드 열린 상태, 하단 시스템 영역에서 버튼과 오류가 잘리지 않는지 확인한다. 현재 UI에는 자동화 식별자가 있지만 식별자가 있다는 것만으로 접근성 검증이 끝난 것은 아니다.

근거: M `features/settings/settings_page.dart`, `features/transactions/transaction_widgets.dart`, `features/bank_accounts/account_pickers.dart`, `core/test_id.dart`.

## 웹과 맞출 것과 앱에서 유지할 것

계좌 없음의 권한, 금액 단위, 서버 승인 기준, 오류 이유, 거래 공개 범위는 웹과 앱에서 같아야 한다. 알림 배지 0 표시처럼 서로 다른 표현은 사용자 혼란이 있는지 보고 정한다. 현재 웹은 0과 99+를 표시하고 앱은 0 배지를 숨긴다. 네이티브 관례에 맞는 0 숨김을 바로 기능 누락으로 취급할 필요는 없다.

하단 탭, 아래로 당겨 새로고침, 네이티브 뒤로 가기, 포그라운드 SSE는 모바일 특성에 맞게 유지한다. 웹의 Playwright 시연 패널과 DB 조회 패널은 일반 사용자 금융 기능과 분리하고 이번 일치 작업에 자동으로 포함하지 않는다.

외부 입금의 소통 UI와 기본 공개 범위 이전값 처리 정책을 먼저 정한 뒤 화면 문구를 확정한다. README의 화면 설명과 이미지는 구현 완료 후 실제 모습으로 갱신한다.

## 완료 검토 순서

1. 정상 사용: 가입, 로그인, 계좌 등록, 입금, 상대 검색, 이체, 거래 확인, 알림 읽음, 설정, 로그아웃.
2. 서버 거절: 잘못된 비밀번호, 잔액 부족, 삭제된 계좌, 수취 잔액 한도, 계좌 등록 한도, 중복 좋아요, 접근 불가 거래.
3. 복구: 전송 후 응답 손실, 승인 후 조회 실패, 로그인 만료, 백그라운드 복귀, 네트워크 변경.
4. 화면 경합: 연속 탭, 처리 중 뒤로 가기, 조회 중 사용자 전환, 다음 페이지 조회 중 필터 변경.
5. 기기 표현: 작은 화면, 글자 확대, 긴 문구, 키보드, 접근성 읽기.

이 목록은 사용자 관점의 검토 범위다. 자동화 테스트의 파일 구성과 생성 순서는 사용자가 정한다. M의 축약 경로는 `apps/mobile/lib/` 아래를 뜻한다.
